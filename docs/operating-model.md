# Operating Model

## 系统分层
- `01_inbox` 处理未结构化输入。
- `02_workspaces` 处理单个问题的分析和验证。
- `03_workflows` 规定高频任务的处理方式。
- `04_templates` 提供统一骨架，降低重复劳动。
- `05_assets` 存放复用价值高、相对稳定的方法论和规则。
- `06_decisions` 存放最终判断和后续复盘。

这六层不要混用。
临时分析不要直接写进资产库，长期原则不要塞进工作区。

## 证据强度分级
- `强`
  直接来自广告平台、产品后台、素材测试、真实用户行为或多轮重复验证。
- `中`
  来自多个可信外部来源、单轮但样本尚可的测试，或能被内部数据部分佐证的观察。
- `弱`
  个别案例、未完全核实的市场传闻、小样本观察或强依赖主观解释的推测。

所有重要结论建议标注证据强度。
当证据强度为 `弱` 时，默认只能作为假设，不能当成业务结论。

## 文档路由规则
- 原始截图、链接、会议结论、随手问题，先放 `01_inbox`。
- 某个问题需要拆解假设、列验证动作时，建立 `02_workspaces` 文件。
- 某类问题重复出现 3 次以上，且处理方式相似，应补充或更新 `03_workflows`。
- 某个结论具有跨项目复用价值时，进入 `05_assets`。
- 涉及继续、暂停、加码、转向、放弃的正式决定，进入 `06_decisions`。

## 资产化判断标准
满足以下至少两项时，应考虑从工作区升级到资产库：

- 在多个项目、多个市场或多个周期里重复出现。
- 已被至少一次真实业务动作验证有效。
- 对收入、增长、创意效率或决策速度有明显影响。
- 能被整理成明确的规则、信号或方法，而不是一次性描述。

## 冲突处理规则
- 新证据推翻旧判断时，优先更新旧文档，而不是并列保留两个版本。
- 若需要保留历史版本，必须明确标记 `已废弃`、`适用条件变更` 或 `等待复核`。
- AI 与人类经验结论冲突时，应写清冲突点、证据来源、假设条件和最低成本验证动作。

## 默认分析输出标准
任何值得被保存的分析，至少应包含以下要素：

- 问题是什么
- 假设有哪些
- 已有数据是什么
- 缺失数据是什么
- 最小验证动作是什么
- 决策阈值是什么
- 下一步动作是什么
